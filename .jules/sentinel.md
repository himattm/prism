## 2025-02-14 - Predictable Temp File Symlink Vulnerability

**Vulnerability:** Found multiple instances of atomic file writes where a temporary file was created using a predictable name (e.g., `path + ".tmp"`) in a shared system directory (`os.TempDir()`), followed by `os.WriteFile` and `os.Rename`.
**Learning:** Using predictable file names in a world-writable directory like `/tmp` leaves the application vulnerable to symlink attacks. An attacker can create a symlink with the predictable temporary file name pointing to a critical system file. When the application writes to the temporary file, it inadvertently writes to the symlinked file, potentially overwriting it or elevating privileges.
**Prevention:** To prevent this, always use `os.CreateTemp` to generate unpredictable, uniquely named temporary files. Furthermore, create the temporary file in the same directory as the target file (`filepath.Dir(path)`) instead of `os.TempDir()` to prevent cross-device or mount-point rename errors. Ensure proper file cleanup (e.g., closing and removing the temporary file on error) and correctly configure file permissions if necessary, as `os.CreateTemp` defaults to `0600`.

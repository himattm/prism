## 2025-04-20 - Prevent Symlink Attacks in Shared Directories during Atomic File Writes
**Vulnerability:** Symlink attack vulnerability in `internal/sparkline/sparkline.go` and `internal/burnrate/burnrate.go` during atomic file writes in shared directories (like `os.TempDir()`). The code used predictable temporary file names (e.g., `path + ".tmp"`) with `os.WriteFile` before calling `os.Rename`. An attacker could pre-create a symlink at the predictable path pointing to a sensitive file, causing the write operation to overwrite that sensitive file.
**Learning:** Shared directories like `os.TempDir()` are accessible by multiple users. Using predictable file names in such directories allows malicious actors to exploit race conditions or pre-create symlinks.
**Prevention:** Use `os.CreateTemp` to generate unpredictable temporary file names. Because `os.CreateTemp` defaults to 0600 permissions, explicitly call `f.Chmod(perm)` if matching original `os.WriteFile` permissions is required. Always call `f.Close()` before renaming to prevent errors on Windows. Ensure the temporary file is cleaned up via `defer os.Remove(tmp)`.
